- 선택적 매개변수(?)
  : 해당 매개변수를 넣어도 되고 안 넣어도 된다는 의미.
  : 선택적 매개변수에 대해 기억해 두어야 할 또 가른 점은, 필수 매개변수 뒤에만 올 수 있다는 점.(먼저 나올 수 없음.)
  ex)
  function greet(name?: string): string{
  //return `Hello, ${name}!`; ☞ 오류
  return name? `Hello, ${name}!`: `Hello!`;
  }
  ☞ 이렇게 작성했을 경우 함수 내부의 'name' 값은 문자열 또는 undefined
  ☞ 선택적 매개변수를 사용할 때는 선택적 매개변수의 값에 따라 결과가 달라지기 때문에 위처럼 if 문을 사용, 그렇지 않을 경우, name이 undefined인 경우를 처리하지 못해 오류가 남.

- 선택적 매개변수와 필수 매개변수의 개수
  ex)
  function add(a: number, b: number, c?: number): number{
  return b&&c? a+b+c: a;
  }

  const addition1 = add(1,2);
  const addition2 = add(1,2,3);
  // const addition3 = add(1); ☞ 오류
  ☞ 매개변수 개수가 허용범위 안이라서 오류

- 나머지 매개변수
  : 함수에 쉼표로 구분된 0개 이상의 인자들을 하나의 배열로 묶어서 받아온다는 의미
  : 나머지 매개변수가 일반 매개변수보다 앞에 올 시 컴파일 오류 발생, 만약 그렇지 않으면 여러 인자들을 전달했을 때 어디까지가 나머지 매개변수로 들어갈 것인지 알 수 없어 오류가 생김.
  ex)
  function sum(...number: number[]): number{
  return numbers.resuce((acc, curr)=> acc\_+ curr, 0);
  }
  console.log(sum(1,2,3), sum(10,20,30,40,50), sum()); ☞ 6,150, 0

- 나머지 매개변수 역시, 일반 매개변수와 함께 사용 가능
  ex)
  function sumItem(item: string, ...args: number[]){
  const sum = args.resuce((acc, curr)=> acc + curr, 0);
  return `${item}: ${sum}`;
  }
  console.log(
  sumItem("apple", 1,2,3),
  sumItem("banana",4,5,6,7,8),
  sumItem("cherry")
  )
  ☞ apple: 6 banana: 30 cherry: 0

- 함수 오버로딩
  : 같은 이름의 함수들이 매개변수의 타입에 따라 다르게 동작하도록 하는 것을 말함.
  ex)
  ☞ 시그니처 작성 필수
  function processInput(value: string): string;
  function processInput(value: number): number;
  ☞ 해당 함수의 매개변수가 문자열일 경우, 문자열을 반환. 숫자일 경우, 숫자를 반환하는 것임을 명시함.

  function processInput(value: string| number): string | number{
  if(typeof value === "string"){
  return value.toUpperCase();
  }else{
  return value \* 2;
  }
  }

  const processed1 = processInput("hello");
  const processed1 = processInput(42);
  //const processed3 = processInput(true); ☞ number 또는 string이 아니라서 오류

  const myString = processed1.toLowerCase();
  ☞ 시그니처를 지울 시 이 값이 문자열이라는 것을 알 수가 없기 때문에 문자열의 메소드를 바로 쓰지 못하도록 함.
  ✔︎ 추가 설명
  ☞ 시그니처가 없다면 타입스크립트는 입력값만을 확신함.
  ex) processed1이 processInput("hello");이었기 때문에 함수는 오류없이 동작, 하지만 출력값은 number 또는 string임. 확신 불가
  ☞ 그렇기 때문에 processed1의 타입을 확신하지 못해 문자열에서만 사용 가능한 toLowerCase()에서 오류가 남
  ☞ 이때, 시그니처를 추가하면 그걸 통해 입력값이 string일 경우, string이 반환 된다는 것을 보고 processed1이 string 타입인 것을 확신.
  ☞ 오류 안 남.
